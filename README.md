# Appalachian Ecozone-Vegetation Analysis

This project analyzes Appalachian forest canopy dynamics across ecozone and forest-community gradients using satellite vegetation indices, terrain/ecological trait layers, PRISM precipitation context, cloudcover threshold, spatial aggregation percentile, temporal aggregation interval and its aggregation percentile, and adjacent growing season curve comparison.

The main user-facing product is a Streamlit dashboard for comparing vegetation-index behavior by AOI, sensor, index, year, thermal ecozone, forest-community group, and forest community.

Forest-community terminology is canonical for the fine ecological categories; thermal ecozone is used for the broader cool/intermediate/hot tier.

## Study Areas

The project uses two Appalachian areas of interest:

- **North AOI:** George Washington / Jefferson National Forest region in Virginia
- **South AOI:** Smoky Mountains / Nantahala-region AOI

The two AOIs are processed independently because of the distance between them and because their forest-community source datasets and category systems are not fully interchangeable.

## Core Questions

This repository supports analysis of:

- wet versus dry year canopy response
- seasonal vegetation-index response curves
- thermal ecozone differentiation
- forest-community differentiation
- north versus south AOI contrasts
- Landsat to Sentinel-2 sensor transition behavior
- PRISM precipitation context versus observed canopy response
- slope/aspect and terrain-related investigations

## Data Sources

Primary input data products:

- **Project AOI footprints** from `AOI/TNC_AOI_LayerPkg/TNC_AOIs.shp`
- **Sentinel-2 Level-2A** from Microsoft Planetary Computer STAC
- **Landsat Collection 2 Level 2** from Microsoft Planetary Computer STAC
- **PRISM monthly precipitation** for precipitation context and wet/dry year classification
- **TNC Appalachian forest-community/ecozone datasets** for ecological stratification
- **Copernicus DEM GLO-30** for terrain derivatives and slope/aspect investigations

Derived vegetation indices:

- **NDVI:** vegetation greenness/productivity
- **NDMI:** canopy moisture response
- **EVI:** vegetation greenness with reduced saturation/soil influence

## Dashboard

The dashboard entry point is:

```bash
streamlit run dashboard_app.py
```

Recommended setup from the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dashboard.txt
streamlit run dashboard_app.py
```

On Windows Command Prompt or PowerShell:

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dashboard.txt
streamlit run dashboard_app.py
```

Python 3.12 is recommended because that is the tested development environment. Python 3.10 or 3.11 may also work if dependency wheels install cleanly.

## Dashboard Data

The dashboard does not read raw satellite rasters at runtime. It uses precomputed summary tables in:

```text
SummaryTables/dashboard_data/
```

Runtime data products include:

- manifest files describing available summary slices
- partitioned Parquet datasets for fast dashboard filtering
- optimized Parquet fallback tables
- PRISM precipitation year-classification data in `config/`

The dashboard data are generated by table-factory scripts from cached Sentinel-2/Landsat index rasters and aligned trait rasters.

Interpretation note: the accepted Sentinel-2 cache was not harmonized for the early-2022 Sentinel-2 processing-baseline shift. Abrupt Sentinel-only changes around 2022 may reflect product processing rather than canopy response; see `docs/DATA_METHODS_SHORT.md` and `docs/DATA_PROVENANCE_AND_CACHE_CHARACTERISTICS.md`.

## Dashboard-Only Handoff

A dashboard-only user package can be built from:

- `dashboard_app.py`
- `src/`
- `config/`
- `requirements-dashboard.txt`
- `SummaryTables/dashboard_data/`

Dashboard-only users do **not** need raw Sentinel-2, Landsat, PRISM, DEM, AOI raster caches, or table-rebuild scripts.

The current Windows-safe handoff package is stored locally under:

```text
Deliverables/AppDash/
Deliverables/AppDash.zip
```

`Deliverables/` is intentionally ignored by git.

## Main Processing Flow

High-level rebuild path:

1. Acquire/cache Sentinel-2 and Landsat index rasters.
2. Prepare AOI-aligned terrain, thermal ecozone, and forest-community trait rasters.
3. Download or ingest PRISM monthly precipitation and build AOI-level precipitation classifications.
4. Build scene-level and temporal dashboard summary tables.
5. Build thermal-ecozone, forest-community, and forest-community-group summaries.
6. Optimize summary tables into Parquet and partitioned Parquet.
7. Run the dashboard against `SummaryTables/dashboard_data/`.

Key scripts:

- `Cache/build_sentinel_cache.py`
- `Cache/build_landsat_cache.py`
- `Preprocessing/Traits/ForestCommunity/prep_forest_community.py`
- `Preprocessing/Traits/Terrain/build_elevation_cache.py`
- `Analysis/DashboardPipeline/TableFactory/build_dashboard_tables.py`
- `Analysis/DashboardPipeline/TableFactory/build_dashboard_ecozone_tables.py`
- `Analysis/DashboardPipeline/TableFactory/build_dashboard_forest_community_tables.py`
- `Analysis/DashboardPipeline/TableFactory/optimize_dashboard_ecozone_parquet.py`
- `Analysis/DashboardPipeline/Climate/build_prism_growing_season_precip.py`

## Reproducibility Notes

The project can be reproduced or handed off at three practical levels:

- Dashboard-only use. 2-10 GB storage. 8-16 GB RAM.
- Dashboard table rebuild from existing caches. 500-700+ GB storage. 16-32 GB RAM.
- Full raw-to-dashboard workspace. 600 GB - 1 TB+ storage. 32 GB RAM.

Dashboard-only use needs the app code and precomputed summary tables.
Full reproducibility from raw/cached inputs requires the AOI source data, satellite caches, PRISM rasters, generated rasters, and table factory outputs.

Generated outputs, rasters, cache directories, deliverable zips, local paths, and virtual environments are intentionally excluded or ignored in git.
